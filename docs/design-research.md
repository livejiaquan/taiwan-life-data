# 設計筆記

這是我做網頁介面前後整理的筆記：看了哪些同類產品、借了什麼、為什麼這樣取捨，以及最後落在 `apps/web/src/styles.css` 的設計 token。

## 要解決的問題

網站只回答一個問題：**今天出門要注意什麼**。資料來自好幾個官方來源，新鮮度不一，過舊時不能下結論。所以設計上有三個要求：

1. 第一屏就看到結論，不用捲動。
2. 每一項都看得到資料時間。
3. 「過期不下結論」要看得出來，不能被讀成「沒事」。

## 看過的產品與借鏡的地方

| 產品 | 借鏡 | 不採用 |
|---|---|---|
| Apple 天氣 | 警報放在最上面；卡片＝圖示＋標題＋一個判讀詞＋一句白話 | 動態天空背景（會干擾警示色的意義） |
| Google 天氣 | 「目前狀況」用等大的小格一次排出多個指標；手機單欄、寬螢幕多欄 | — |
| CARROT Weather | 固定的重點順序；每個區塊自帶一致的小標題列 | 自訂版面、俏皮文案（防災資訊不適合） |
| Yahoo 天氣 | 首屏只回答一個問題 | 全幅照片（沒有授權圖源，也拖慢首次繪製） |
| 中央氣象署 W | 沿用官方用語與等級名稱；每項連回官方資料集 | — |
| tenki.jp 生活指數 | 「圖示＋等級詞」一列排開 | — |
| MeteoAlarm | 綠黃橙紅色階、語言無關的圖示；缺漏／過舊是獨立狀態 | — |
| Yr.no | 淡色頁底加白卡、1280px 容器、地名＋小字副標＋分頁列、摘要卡 8/12 寬、滿版白列（高 72、列距 8）、8px 圓角、幾乎看不見的陰影 | 品牌、圖示、字型、色票 |

沒有一個產品把「資料多新」當成一級資訊——這是本站要放大的差異。

## 版面

參考 Yr.no 的預報頁，量過它的容器寬、卡片比例、列高、圓角與字級後，把節奏套到自己的內容：

- 頁首：品牌在左、外觀切換在右；下面是地名、小字副標、頁面分頁；縣市與鄉鎮下拉在右側。
- 「今日重點」卡：8/12 寬。總結句是唯一焦點（桌面 64px、手機 40px，明體），依當天最高等級上色；下面是五項的「圖示＋等級詞」。
- 五項細節：滿版白列，欄位是項目、判讀、資料時間；警特報列左側有等級色條。
- 手機：單欄，卡片離邊 8px，摘要卡有淡色漸層。

## 警示視覺語言

- 等級 `ok → notice → warn → danger` 對應綠、黃、橙、紅（Radix Colors 的 3／7／9／11／12 階），**每個顏色都配文字**（正常、留意、注意、警戒），顏色不是唯一訊號。
- 過舊或讀不到是第五種狀態：灰色、斜紋底、虛線框、文字寫「過舊」或「讀不到」，總結句寫「N 項資料過舊或讀不到，這幾項不下結論」。全部讀不到時，總結改寫「目前讀不到資料，不下結論」，不用大字顯示「沒事」。
- 每一列固定顯示狀態膠囊、資料時間與「約 N 小時前」；資料集與更新頻率收進「資料來源」展開區。

## 設計 token

- **字級**：14 / 16 / 18 / 22 / 30 / 40 / 64 / 96 px。內文與清單 16px（行高 1.7），時間戳、膠囊、欄名 14px，12px 只用在逐時圖軸標。
- **間距**：4 / 8 / 16 / 24 / 32 / 48 / 80。
- **字體**：內文用系統黑體，不載入網路字型（中文字型檔大，會拖慢手機首次繪製，也多一個第三方請求）；總結句與數字焦點用系統明體或系統數字字型。
- **色彩**：中性色是自己的墨藍系（淺色 `#e9f1fb` 頁底、白卡、`#0f1e33` 字；深色 `#0c1420` 底）；狀態色來自 Radix Colors 3.0.0（MIT）。
- **圓角**：卡片 8、按鈕 4、膠囊 999。
- **圖示**：全部用 Lucide（`lucide-react`，ISC），24px 格、筆畫 1.75、圓角端點、`currentColor`，尺寸只用 16／20／24。
- **品牌標記**：圓角方形（圓角 22%）石板藍 `#315ab9`，中間白色 Lucide `compass`。
- **動效**：只有一個——五項資料都讀完時，總結句的顏色轉成當天等級色；`prefers-reduced-motion` 時關閉。
