# 技術決策

這份文件記錄幾個影響資料正確性與架構的決策與取捨。編號固定，其他文件會引用。

## 原則

- **過舊不下結論（fail-closed）**：沒有資料 → 無法取得；時間缺失、無法解析或比現在晚 15 分鐘以上 → 過舊；超過門檻 → 延遲／過舊。過舊或無法取得時，網站與 MCP server 都不輸出任何判斷。
- **狀態永遠在顯示當下重算**：檔案裡存的 `status` 只是收集當下的判定，讀取端依資料年齡自己重新判定。
- **金鑰不進瀏覽器**：公開建置會掃描產物，出現金鑰字樣或需金鑰的 API 網址就失敗（D6）。

## D1. Monorepo 結構

`packages/contract`（資料契約、新鮮度、事故）→ `packages/collectors`（解析與驗證）→ `packages/assess`（判讀）→ `apps/web`（Vite＋React）與 `packages/mcp-server`。網站與 MCP server 共用 `packages/assess`，同一筆資料一定得到同一個結論（例如 AQI「普通」在兩邊都不點名）。

## D2. 新鮮度方案：能直接讀官方檔的，由瀏覽器補抓

**量測**：GitHub Actions 的 `schedule` 實際間隔很不準——三個舊專案的相鄰觸發間隔中位數 135–299 分鐘、p95 406–442 分鐘，遠達不到「資料年齡 p95 ≤ 30 分鐘」，只能當備援。

**各官方端點能否由瀏覽器直接讀**（以 `curl -H 'Origin: …'` 實測）：

| Feed | 免金鑰 | CORS | 結論 |
|---|---|---|---|
| 警特報、UV 觀測、熱傷害、鄉鎮預報（氣象署 S3 公開檔） | 是 | `*` | 瀏覽器直接讀 |
| 水庫（水利署） | 是 | `*` | 瀏覽器直接讀 |
| AQI（環境部） | 否，需 `api_key` | — | 只能伺服器端收集 |
| 電力（台電） | 是 | 無 CORS 標頭 | 只能伺服器端收集（D18） |

**決定**：先讀同源快照，依「現在」重算狀態；不是即時才去讀官方檔，讀到就用、讀不到退回快照（快照過舊就不下結論）。AQI 與電力維持伺服器端收集，新鮮度取決於收集排程。

## D3. AQI 金鑰

優先使用 GitHub secret `MOENV_API_KEY`；未設定時改用環境部刊登在 data.gov.tw 資料集 40448 的公開下載連結（執行時解析、不入庫、不進瀏覽器）。共用金鑰有每日呼叫上限，被限流時 API 會回 HTML 而不是 JSON，收集器因此判定失敗並保留上一份快照（過舊後不下結論）。正式運作建議設定自己的金鑰。

## D4. 熱傷害資料

data.gov.tw 143330 的下載連結會轉址到氣象署 S3 的 `M-A0085-001.json`，該檔免金鑰，直接使用。時間格式為 `+8:00`（單位數時區），解析已處理並有測試。368 鄉鎮必須全數存在，少一個整檔拒收。

## D5. 各 feed 新鮮度門檻（`packages/contract/src/feed.ts`）

| Feed | 依據 | 即時 ≤ | 延遲 ≤ | 理由 |
|---|---|---|---|---|
| warnings | 最近成功讀取時間 | 15 分 | 60 分 | 事件型檔案，沒有固定更新節奏 |
| uv | 最新觀測時間 | 25 分 | 120 分 | 每 10 分一筆＋發布落差約 10 分 |
| heat | 發布時間 | 7 小時 | 13 小時 | 每 6 小時一報 |
| aqi | publishtime | 80 分 | 180 分 | 每小時＋約 20 分發布落差 |
| rain | IssueTime | 7.5 小時 | 13 小時 | 一天 4 次發布，加上檔案出現的落差 |
| power | 觀測時間 | 30 分 | 90 分 | 每 10 分更新 |
| reservoir | 最新一座的觀測時間 | 3 小時 | 12 小時 | 每小時（部分水庫每日） |

「即時」窗不得超過目標新鮮度，否則前端會沿用舊快照而不去官方檔更新。

## D6. 公開建置防金鑰

建置步驟的環境變數出現任何金鑰即中止；`collect` 是唯一拿得到 secret 的步驟。建置後掃描所有產物：「參數名後面跟著像金鑰的值」（`api_key=` 後接 8 個以上字元）以及需金鑰的 API 網址（`data.moenv.gov.tw/api/`、`opendata.cwa.gov.tw/api/`）都算洩漏。AQI 網址組裝程式只放在伺服器端模組（`packages/collectors/src/server.ts`），前端只引用氣象署的部分。

## D8. 紫外線不借鄰近縣市

全台約 30 個測站有紫外線值。沒有測站的縣市顯示「本縣市沒有紫外線測站，不推估」，不借鄰近縣市的值，避免把推估當成觀測。

## D10. 368 鄉鎮與選擇方式

`scripts/gen-towns.ts` 從熱傷害資料（368 鄉鎮全量，含 geocode 與中心點）產生 `packages/contract/src/towns.ts` 並入庫；筆數不是 368 就失敗。同一組 geocode 也是鄉鎮預報的 `Geocode` 與觀測站的 `TownCode`，各 feed 以 geocode 對應鄉鎮，不靠名稱（「東區」在 4 個縣市都有）。介面用縣市、鄉鎮兩個原生 `<select>`，網址 `?county=&town=` 可分享，並記住上次選擇。

## D11. 降雨：各縣市鄉鎮 3 天預報

資料源是氣象署 F-D0047 每縣市一檔（0.6–1.1 MB）。快照只留未來 24 小時的「3 小時降雨機率」與「天氣現象」，368 鄉鎮 gzip 約 6.6 KB。驗證：縣市名必須與檔號相符、該縣市每個鄉鎮都要在，少一個整檔拒收，避免「沒有預報」被讀成「不會下雨」。快照缺某縣市時，瀏覽器只補抓所選縣市那一檔。

## D12. 鄉鎮級判定

| Feed | 作法 |
|---|---|
| 警特報 | 縣市層級（官方就是以縣市發布），並明寫「以縣市為單位發布」 |
| 熱傷害、降雨 | 該鄉鎮自己的官方逐 3 小時資料 |
| 紫外線 | 同縣市內距離鄉鎮中心最近的測站，顯示距離；不跨縣市 |
| 氣溫 | 優先同鄉鎮（`TownCode`）的測站，否則同縣市最近 |
| 空品 | 同縣市內最近測站為主，另列縣市最高值 |

摘要只點名需要留意的項目；AQI 51–100 維持黃色但不在摘要點名；無法判斷的項目一律寫「無法判斷」，不會算成「正常」。

## D13. 效能：預先渲染＋hydration

首頁、今天的台灣、資料狀態三頁都在建置時預先渲染，第一次繪製不需要 JS；CSS 內嵌。讀取中的區塊預留載入後的高度，避免版面跳動。地點在 hydration 之後才決定，所以預先渲染的內容與第一次 client render 相同。

## D14. 狀態紀錄與事故，不用資料庫

每次收集先從線上讀回上一份 `data/status.json`，併入這次結果再發布。歷史因此跨部署累積，不需要資料庫。某 feed 這次收集失敗時，改發布上一份快照（加註失敗原因），顯示時仍依年齡重新判定。事故類型：收集失敗、資料過舊、收集中斷（兩次收集相隔超過 60 分鐘；收集器停擺時無法記錄自己，所以由讀取端依最後一次收集時間即時計算）。限制：只量得到「收集當下」的快照年齡；瀏覽器直接讀官方檔時的實際年齡沒有回傳管道（不做追蹤）。

## D15. LINE 分享

文字分享用 LINE 官方 URL scheme，另有複製文字；圖卡用 Canvas 自繪 1080×1350 PNG（不加套件），支援 Web Share 的手機直接叫出分享面板。每一項都附狀態與資料時間，過舊的項目分享的是「不做判斷」。

## D17. 個別測站與時段也要 fail-closed

不只整個 feed，每個測站、每個時段也各自判斷：觀測時間過舊的測站不採用，預報沒有涵蓋「現在」的時段顯示「預報沒有涵蓋現在這個時段」。

## D18. 電力：台電機組與供需，只能伺服器端收集

資料源是台電「各機組發電量即時資訊」（含外購電力，data.gov.tw 8931）與「今日系統供需狀況」（162595）。回應沒有 `Access-Control-Allow-Origin`，瀏覽器不能直接讀。驗證：非小計機組 ≥ 100、可讀發電量比例 ≥ 98%、單機 −20,000～100,000 MW、時間不得晚於現在 15 分、一次發電總量 5,000～60,000 MW。檔案開頭有 UTF-8 BOM，解析已處理。超過 90 分鐘不顯示目前碳強度。

## D19. 水庫：20 座主要水庫，逐座 fail-closed

資料源是水利署「水庫水情資料」（45501，每小時）與「水庫每日營運狀況」（41568，提供有效容量），免金鑰且允許跨網域。範圍為 20 座主要水庫，少於 10 座整份拒收。規則：晚於現在 15 分以上的列丟棄再取每座最新一筆（實測曾出現比現在晚 5 小時的觀測）；超過 48 小時的水庫只顯示「資料過舊，不顯示」。蓄水率超過 100%（例如阿公店水庫曾為 131.5%）照官方數字呈現，長條圖封頂；頁面註明「蓄水率不等於限水」。

## D20. 碳強度方法；綠電時段只用本站存檔

公式與係數見 [`METHODOLOGY-carbon.md`](METHODOLOGY-carbon.md)。主要指標是生命週期碳強度（可與 Electricity Maps 比較），同時提供直接排放。儲能不計入分子與分母。**綠電時段不用台電的歷史檔 d006010**：它有逐 10 分鐘機組資料，但實際解析後只含台電自有機組（例如某日 12:00 太陽能只有 84 MW），算出的逐時碳強度幾乎是平的（617–623 g），會誤導。綠電時段改由本站歷史存檔計算，代價是新站要累積一到兩週才會出現。

## D21. 歷史存檔：`data` 分支、一 feed 一天一檔、90 天

選用 repo 的 `data` 孤兒分支：格式 `v1/<feed>/<YYYY-MM-DD>.json`（台北日期）加 `v1/index.json`；同一個官方更新（同 `sourceTime` 且內容相同）只存一次；分支最新版只留最近 90 個台北日，更舊的在 git 歷史。第一次存檔 7 個 feed 共 64 KB，預估每天小於 1.5 MB。存檔同時鏡像進網站（`archive/v1/…`）。

## D22. 開放 JSON API：靜態檔加文件

API 就是 GitHub Pages 上的靜態 JSON（`Access-Control-Allow-Origin: *`），另有機器可讀的 `data/catalog.json`。文件只寫一份（[`API.md`](API.md)）；站內「資料狀態」頁有簡短格式說明。`schemaVersion: 1` 內只新增欄位，不相容時換路徑（`archive/v2/`）。

## D23. 「今天的台灣」放獨立頁

首頁有效能預算（LCP ≤ 1.5 s、首屏 JS ≤ 150 KB），電力與水庫放獨立的 `/today/` 頁，同樣預先渲染與 hydration。

## D26. 判讀邏輯獨立成 `packages/assess`

為了讓 MCP server 與網站用同一套判讀，把純函式（`assess.ts`、`today.ts`、`pick.ts`、`card.ts`）抽成獨立 workspace，行為不變，測試隨檔案搬移。取捨是多一個套件，換來兩邊結論一致。

## D27. MCP server

- **讀資料順序**：先讀網站快照並依現在重算狀態；不是即時（或雨量快照沒涵蓋該縣市）就在使用者電腦上直接讀官方資料，用同一份 parser 與驗證。沒有鄉鎮時不讀雨量；失敗的讀取不快取。
- **輸出**：每個工具回傳繁體中文純文字，每項都有狀態、資料時間、資料年齡、取得方式與官方資料集；過舊或無法取得時用與網站相同的句子，不出現數值。
- **工具**：`outdoor_brief`、`list_towns`、`grid_carbon`、`reservoirs`、`data_status`、`history`，全部標示唯讀。
- **打包**：esbuild 把 SDK 與 workspace 套件打成單一 `dist/index.js`，沒有執行期依賴。
- **安裝**：npm 套件名 `taiwan-life-data-mcp`；尚未發佈到 npm 時，同一份 `npm pack` 的 tarball 掛在 GitHub Release，用 `npx -y --package=<tarball URL> taiwan-life-data-mcp` 安裝（直接 `npx <tarball>` 會被當成要執行該檔而失敗）。

## D29. 事故紀錄的延伸

事故除了 `status.json`（最近 100 件），另有 Atom feed（`data/incidents.xml`）與 90 天長期紀錄（`archive/v1/incidents.json`，依結束時間保留，長事故結案後不會立刻消失）。事故記錄持續次數與最差資料年齡。
